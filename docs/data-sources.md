# 数据源说明

本文说明地址编码服务用到和推荐使用的数据从哪里来、能否再分发、坐标系与时效如何、怎样接入，以及仓库内置的每份数据各自的出处。接入步骤见 [data.md](data.md)，技术选型见 [tech-selection.md](tech-selection.md)。

文中“实测”数字均来自本仓库脚本在 2026-10-16 的运行结果。

|---|---|---|---|---|

## 2. 选源原则

1. **许可清晰、可再分发**：内置到仓库的数据必须是公共领域或开放许可（CC0、WTFPL、ODbL 等），并保留来源和署名。
2. **官方优先，开放数据补充**：区划代码以民政部、国家地名信息库为准；坐标、道路等官方不提供批量开放数据的部分，用 OpenStreetMap 派生数据补充。
3. **不使用商业图商数据**：不抓取、不转存高德、百度、腾讯等地图服务的数据（含其 API 返回结果的批量缓存），也不使用由它们派生的“开源”数据包。
4. **坐标系明确**：每份数据标注坐标系，入库统一转 WGS84（见 `coords.py`）。
5. **可复现、可验证**：内置补充数据都由 `scripts/sources/` 下的脚本生成，记录源版本；生成后做交叉校验。

## 3. 行政区划代码

### 3.1 统计用区划代码 2023（乡级基线）

- **文件**：`data/admin/provinces.csv`、`cities.csv`、`areas.csv`、`streets.csv`（省 31、地 342、县 2,978、乡 41,352 条）。
- **出处**：国家统计局《统计用区划代码和城乡划分代码》2023 版（截至 2023-06-30），社区整理版 [modood/Administrative-divisions-of-China](https://github.com/modood/Administrative-divisions-of-China)，WTFPL 许可。
- **时效**：该项目说明，国家统计局自 2024 年 10 月起继续公开编制规则，但不再公开具体代码，因此 2023 版是可获得的最后一版乡级全量数据。
- **特点**：除正式行政区外，还含 135 个统计用的开发区、管理区（编码第 5 位为 7 等），乡级代码会引用它们，所以保留。
- **已知问题**：少数乡镇名称带了区县前缀（如“济源市沁园街道”），加载时自动去掉。

### 3.2 县级以上区划代码 2025 更新

- **文件**：`data/admin/extra.csv`（8 条）。
- **出处**：[yescallop/areacodes](https://github.com/yescallop/areacodes)，CC0 1.0。该项目收录 1981–2025 年县级以上区划代码 6,824 条记录及新旧代码对应关系，数据取自国家地名信息库 2025 年行政区划代码、民政部历年《中华人民共和国县级以上行政区划代码》和《县级以上行政区划变更情况》。
- **补充内容**：统计用 2023 版之后新设或缺漏的现行区划：三沙市西沙区、南沙区（2020），新疆和田地区和康县、和安县（2024），重庆市两江新区（2025）；以及按 GB/T 2260 补充的台湾省、香港特别行政区、澳门特别行政区省级代码。
- **生成**：`python scripts/sources/areacodes.py`。

### 3.3 区划历史旧名

- **文件**：`data/admin/history_aliases.csv`（1,015 条，覆盖 989 个历史名称）。
- **出处**：同 3.2。脚本沿“变更 / 撤销 → 新代码”链条追到现行代码。同一代码在不同年份可能指代不同区域，追溯时按年份取对应记录。
- **用途**：解析使用旧名的地址，如“崇文区”→110101 东城区、“萧山市”→330109 萧山区、“万县市”→500101 万州区、“海门市”→320614 海门区。
- **过滤规则**：
  - 与任何现行名称同名的旧名不收（现行名优先，如“巢湖市”）；
  - “郊区”“城区”“矿区”等泛称不收；
  - 指向超过 3 个现行区域的名称不收。
- **权重**：匹配权重低于现行全称和人工别名（`aliases.csv`），只在没有更好解释时生效。

### 3.4 官方渠道与更新机制

- 《行政区划代码管理办法》（民政部令第 79 号，2025-09-01 起施行）规定：省级、地级、县级代码由国务院民政部门确定；乡级代码由省级民政部门确定，每年 1 月和 7 月发布。
- 官方查询入口：国家地名信息库（dmfw.mca.gov.cn）、全国行政区划信息查询平台（xzqh.mca.gov.cn）。
- 本仓库的更新方式：县级以上随 areacodes 更新后重跑脚本；乡级在统计局停更后，需要从各省民政部门的半年度发布整理，目前尚未自动化，作为后续工作。

## 4. 行政区划中心点

- **文件**：`data/admin/centroids.csv`（38,428 条，WGS84）。建库时自动加载，用于：
  - “北京市海淀区”这类只到区划的地址返回坐标；
  - 没有边界数据时，逆地理用最近区县中心点兜底。
- **出处**：[Overture Maps Foundation](https://overturemaps.org/) divisions 主题，发布版本 2026-09-23.1。该主题的中国数据来自 OpenStreetMap（少量来自 Esri Community Maps，CC0），按 ODbL 1.0 许可。
- **生成方法**（`python scripts/sources/overture.py admin`）：
  1. 读取公开 S3 桶中的 GeoParquet，按行组 bbox 统计裁剪，只读取中国范围（约 57 万个区划点，用时约 25 秒）。
  2. 省级用 ISO 3166-2 代码对应 GB 代码；地级、县级在同一省内按中文名称匹配，同名时用层级链里的上级名称区分；乡级在所属区县范围内按名称匹配。
  3. 坐标优先取区划**驻地**（`capital_division_ids` 指向的城镇点，与常用地图服务给出的区划中心一致），没有驻地时取区划标注点。
     - 北京市人民政府 2019 年迁至通州，“北京市”按惯例取市中心标注点（天安门一带）。
  4. 合理性检查：子级距上级中心过远的剔除（区县 400 km；内蒙古、四川、西藏、甘肃、青海、新疆为 800 km；乡镇 150 / 300 km）。
- **覆盖率（实测）**：

  | 层级 | 匹配 | 说明 |
  |---|---|---|
  | 省级 | 31 / 34 | 港澳台在 Overture 中不归入 CN |
  | 地级 | 332 / 333 | 缺三沙市 |
  | 县级 | 2,851 / 2,983 | 未匹配的 132 个里 124 个是统计用开发区；其余为金门县、南海诸岛相关 6 个、重庆江北区与渝北区（OSM 缺这两个区的区划关系） |
  | 乡级 | 35,214 / 41,352（85%） | 剔除 7 个飞地或兵团团场乡镇（距所属区县 300 km 以上，如马鬃山镇、天津铁厂街道） |

- **校验（实测）**：
  - 用同一版本的 Overture 区划面做点落面检查：区县中心点 2,847 / 2,851 落在本区县内（其余 4 个为驻地设在相邻区的情况），乡镇中心点 35,211 / 35,214 落在所属区县内。
  - 与示例数据中按驻地录入的 19 个近似中心点对比，15 个相差不到 1 km；余杭区相差 35 km，是因为 2021 年析置临平区后区政府迁址，Overture 的数据更新。
- **许可义务**：本文件是 ODbL 派生数据库，单独成文件并在文件头注明 ODbL 和署名“© OpenStreetMap contributors, Overture Maps Foundation”。
  - 再分发时须保持 ODbL 许可，对外提供服务时须标注 OpenStreetMap 署名。
  - 这些义务只约束该数据文件，不影响仓库代码本身的许可。

## 5. 行政区划边界

边界用于逆地理点落面（`admin_source=boundary`），能显著提高区县判定准确率。**边界涉及国界、争议地区表示和审图要求，仓库不内置。** 按以下顺序选用：

| 来源 | 说明 | 建议 |
|---|---|---|
| 天地图行政区划服务（lbs.tianditu.gov.cn） | 国家地理信息公共服务平台，CGCS2000，需申请 key，按服务条款使用 | **首选**，官方数据 |
| 全国地理信息资源目录服务系统（www.webmap.cn） | 国家基础地理信息中心运维，提供 1:100 万公众版基础地理信息数据（含县级行政区、居民地、道路等），注册后下载 | **推荐**，公众版可公开使用；图层、字段与使用条件以下载说明为准（本环境无法访问，未核实细节） |
| Overture division_area（ODbL） | `python scripts/sources/overture.py boundaries`，输出省、地、县三级 3,210 个面（约 68 MB GeoJSON） | **可选**：仅用于内部判定，不对外展示；OSM 边界未经审核，争议地区表示可能不符合我国标准 |
| DataV.GeoAtlas、Vonng/adcode 围栏等 | 源自高德地图 | **不使用**（第 2 节原则 3） |
| geoBoundaries、Natural Earth | 境外开放数据，名称为拼音，国界表示不符合我国标准 | **不使用** |

实测：用 Overture 边界建库，30 个示例 POI 的区县判定全部正确，全国随机点逆地理平均 0.10 ms。

## 6. 道路

| 来源 | 说明 |
|---|---|
| Overture transportation（ODbL） | `python scripts/sources/overture.py roads --bbox 经度,纬度,经度,纬度`，只保留有中文名的机动车道路。实测北京东城约 3.4 km × 3.3 km 范围抽出 561 条命名路段，名称为标准中文路名（朝阳门内大街、王府井大街等）；按城市范围抽取，全球数据 72 GB，不宜全量 |
| OpenStreetMap 原始数据（ODbL） | Geofabrik 中国分区下载，osmium 转 GeoJSON（见 data.md 第 5 节）。与 Overture 同源，适合需要更多标签时使用 |
| 1:100 万公众版 | 只有主干道路，可作为郊区和农村道路的补充 |

城市主干道覆盖较全；小区内部道路、背街小巷和新建道路需要业务数据补充。

## 7. POI 与门牌

国内没有可批量获取、可再分发的门牌级开放数据，这一层的效果主要靠自有数据积累。

| 来源 | 评价 |
|---|---|
| **自有业务数据** | 价值最高：订单地址 + 签收坐标、司机打点、人工标注。入库前须去除收件人、电话等个人信息（《个人信息保护法》），只保留“地址文本 + 坐标”，坐标系要标清 |
| 兜底回流 | 天地图兜底结果写入待审核日志，人工确认后作为 POI 回流（见 data.md 第 6 节）；需遵守天地图服务条款中关于数据存储的约定 |
| 各地政府公共数据开放平台 | 北京、上海、深圳、浙江等平台发布学校、医院、养老机构、停车场等名录，部分带坐标。各平台条款不同，通常要求注册并注明来源；使用前逐个确认 |
| OpenStreetMap POI（ODbL） | 城市中心区地标、交通设施较全，名称多为中文；门牌稀疏 |
| Overture places | 实测北京中心区约 17 km × 17 km 范围 8,517 条，全部含 CDLA-Permissive-2.0 来源，其中 1,820 条同时来自 Foursquare（Apache-2.0）。名称 65% 含中文（常为中英混排），地址只有 37% 含中文、其余为英文或拼音。可用 `overture.py places --cjk-only` 抽取，**使用前需抽检坐标是否存在偏移**，只作补充 |
| Overture addresses | 实测北京范围 0 条，中国无覆盖 |
| 商业地图 POI、来源不明的“全国 POI 数据包” | **不使用**：违反服务条款或权属不明 |

## 8. 在线兜底服务

- **天地图地理编码**（已实现，`TIANDITU_TK`）：
  - 坐标为 CGCS2000，与 WGS84 按同一坐标系处理；
  - 每日配额和并发上限以账户类型和控制台为准，代码内置配额计数和熔断；
  - 只在本地结果置信度不足时调用。
- **商用 API**（高德、百度、腾讯）：只能按合同使用。返回 GCJ-02 / BD-09 坐标，且服务条款一般限制结果的缓存和转存，不能拿来批量建库。

## 10. 许可与署名

| 许可 | 涉及数据 | 义务 |
|---|---|---|
| CC0 1.0 / WTFPL | 区划代码、历史旧名 | 无强制义务，仍建议注明来源 |
| ODbL 1.0 | 区划中心点；可选抽取的边界、道路；OSM POI | 对外提供服务时署名“© OpenStreetMap contributors”；再分发派生数据库须保持 ODbL；与其他数据合并形成派生数据库时，该数据库同样受 ODbL 约束 |

## 11. 合规要点

以下是工程上需要注意的事项，具体以法务意见为准：

1. **地图展示**：对外公开展示地图须使用经审核的底图并标注审图号；本服务只输出坐标和文本，不提供底图。
2. **边界数据**：未经审核的边界（含 OSM 派生边界）只做内部点落面判定，不对外展示、不对外提供下载。
3. **坐标对外提供**：面向公众的地图类应用在国内通常使用 GCJ-02 坐标，可用接口的 `coordsys=gcj02` 参数输出。对外提供坐标服务的形态需法务确认。
4. **个人信息**：业务地址数据含个人信息，建库前去标识化，日志不保留原始收件信息。
5. **数据出境**：测绘地理信息数据和规模化的位置数据出境受限。海外部署或海外团队访问国内数据前，需要评估。

| 数据 | 上游节奏 | 建议做法 |
|---|---|---|
